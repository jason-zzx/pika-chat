# 服务端托管生成与响应恢复

## 目标

让服务端已经接受的一次生成不依赖浏览器存活。用户切换话题、刷新、关闭网页或退出账号后，服务端继续生成；回来时恢复同一次响应及其状态，而不是重新调用模型。主动停止或删除话题则取消生成。

用户已同意产品方向、单应用实例范围、单话题跨标签页/API互斥及必要依赖升级，并明确授权实施与独立检查。任务为 `in_progress`：实施、两轮精简及自动检查已完成，结果汇总在 `implement.md`。浏览器交互由用户手测，以下完整产品验收不代勾；提交、归档仍未授权。本版替代跨实例/PG流缓存及202/前端重写草案。

## 本轮精简规划（实施与独立检查完成）

用户已审阅并批准最终精简方案，指定 `jason/gemini-4-hydrogen` 实施，完成后由当前主会话模型检查。本轮沿用当前任务，不另建重复任务；实施范围为 design 第10节与 implement 第12节。两项行为缩减均已确认；提交、推送及归档仍未授权。

### 目标与范围

- 在保持浏览器关闭/刷新后后台生成与恢复的前提下，减少同一可信调用链中的重复查询和无人读取的客户端状态。
- 纳入规划：文本执行重复模型解析、admission 锁外重复回执查询与时间窗校验、已建立归属的内部写入链重复权限查询、聊天池遗留 sendContext，以及下述两项已确认的行为缩减。
- 保留：请求收据/时间窗/hash/清理与 pending 恢复、queued 周期补捞、账号隔离、同话题互斥、检查点、终态持久化与流恢复协议。
- 不纳入本轮：终态重试策略重写、遇保存异常自动丢弃正文降级、上下文一致性机制重构、数据库迁移、依赖升级、通用权限/重试框架。已识别的上下文一致性疑点留在研究记录中，不因本轮精简完成而宣称已修复。
- 不把事务执行器 tx 的存在视为权限证明；共享调用入口的归属保护不能因为内部去重而被绕过。

### 本轮验收要求

- SC1：send/regenerate/edit 的模型、消息与版本行为保持一致；消除文本执行分支对同一模型的紧邻重复解析，不取消准备阶段及后台执行阶段各自必要的边界处理。
- SC2：已有收据仍在模型/附件预检之前返回；并发重复请求仍返回同一任务；过期/冲突/删除语义与回执回收规则不变。
- SC3：所有可达业务入口仍拒绝其他账号的 assistant/topic/message；不增加 skipAuth 一类开关，不以 tx 存在作为跳过授权的条件。
- SC4：移除 sendContext 后发送标记、草稿迁移、后台完成与恢复行为不变，不改变服务端标题生成。
- SC5：本轮不增加部署组件、配置或人工维护步骤；自动检查报告区分本轮实跑与既往记录，浏览器手测不代勾。
- SC6（A、R9）：正常启动/开发启动不需要额外配置；实际停机重启验证保留已存内容、正确收尾状态及不重复调用模型，不再要求停机瞬间强制保存最新输出。
- SC7（B、R2/R5）：新发送、重新生成、恢复订阅及停止请求仍校验登录和资源归属；会话失效后拒绝新请求/重连，但既有订阅不再定时核实凭据。客户端正常退出仍销毁页面与订阅，后台任务继续；取消订阅不取消生成，背压与慢订阅隔离不退化。

### 已确认的行为取舍

- A：删除 Next.js 进程信号接管及项目 dev 父进程宽限脚本。正常停机与强杀一样只承诺恢复最近成功持久化的内容；新版启动将遗留 running 标记中断、stopping 收尾为已停止，queued 继续调度，不重调已开始任务。不承诺保存关机瞬间的最新输出；10 秒是检查点尝试间隔而非最大丢失窗口。
- B：删除既有 SSE 订阅的周期会话核实。用户已了解撤销包括退出、改密码或启用两步验证时使其他登录失效，以及封禁导致鉴权拒绝；接受尚未断开的既有连接可能继续收到本次回答。新连接仍鉴权，保留客户端账号切换隔离及显式退出行为。

技术边界见 design 第10节，执行与验证见 implement 第12–13节。最终1279项unit、294项integration、lint/typecheck/build及真实Next start/dev停机恢复验证通过；既有并行reconnect测试波动如实保留。完整浏览器验收、提交及归档仍待用户。

## 背景与证据

- 当前浏览器聊天池仅覆盖 SPA 导航，服务端内存流注册表没有持久化任务身份。`src/server/ai/disconnect-abort.ts` 将浏览器断开与取消上游绑定，与新产品行为冲突。
- `docs/pika-bug-verification-20261104.md` 记录重新生成返回话题后丢失停止入口、删除话题后流继续，以及退出后流继续的实测。跨账号泄漏、实际计费和读流 TypeError 的服务端根因未验证，不作为事实。
- 在新需求下，退出后服务端继续生成是预期行为；问题转为客户端退出隔离和重新登录后的可靠恢复，而不是强制取消。
- `research/open-source-generation-lifecycle.md` 核对LibreChat、Open WebUI及AI SDK官方示例的固定提交：独立生产者、断连仅退订、恢复状态接实时增量与显式停止。研究不等于本项目运行时验证，不照搬外部平台/Redis依赖。
- `research/sdk-upgrade-decision.md` 记录已发布SDK隔离HTTP实验：候选版修复中段恢复重复ID；最小G1确认当前消息状态可初始化同一活跃消息并接续新增量，不需要原始事件日志。项目SDK升级及自动检查已通过；真实UI尚待用户验证。

## 范围与需求

| ID | 需求 |
| --- | --- |
| R1 | 普通发送、重新生成、编辑后重答统一支持后台执行与恢复，保留消息/版本身份及顺序；原有图片模型分支也适用。 |
| R2 | 切换话题、刷新、关闭网页、退出账号不取消已接受的生成。退出关闭客户端订阅并清除账号相关本地状态。 |
| R3 | 返回时已完成则展示最终结果；仍生成中则恢复已有内容、生成状态和停止能力，继续接收同一任务。停止/删除/失败/中断状态不能被迟到的实时更新覆盖。 |
| R4 | 主动停止取消生成并保留已产生的文字内容；图片批次维持既有成功提交/失败清理规则。删除话题或所属助手取消关联生成，迟到输出不得重建已删除数据。 |
| R5 | 创建、查询、订阅、停止均校验账号与资源归属。任务属于用户而非某次登录会话；其他账号不能获取内容或操作任务，旧账号回调不能污染新账号页面。 |
| R6 | 重连、重复提交和同一进程重复调度不得重复执行同一生成任务，不产生重复文字、消息或终态落库。同一话题保留单活跃回合约束，不同话题可以并行。 |
| R7 | 恢复保留已有文字、思考、工具状态、引用、附件及 metadata，包括影响反馈的 finishReason；不破坏版本、压缩、标题、滚动与触屏操作。无浏览器时标题也可生成。 |
| R8 | 默认启用并自动运行，复用现有部署，不新增 Redis、独立 Worker 部署、人工调度或管理开关。不增加全站/进程/账号固定生成并发上限；新请求不因引入后台执行而等待其他话题完成。 |
| R9 | 服务器进程丢失或供应商连接异常时保留已持久化内容，显示失败/中断，不永久“生成中”，不静默重新执行已开始的推理或工具任务。未领取任务可继续调度。 |

## 验收标准

- [ ] AC1（R1–R3）：普通发送、重新生成、编辑后重答分别在生成中切走再返回、刷新、关闭后重开，恢复同一任务；未完成时停止可用，完成时无残留生成状态。
- [ ] AC2（R2、R3、R5）：生成中退出，客户端订阅结束，受保护接口拒绝访问；服务端继续，同账号再次登录恢复已有/最终内容。提交已接受但确认响应丢失时，在任务活跃期间及终态后至少24小时内可凭请求ID找回任务身份而不重发模型请求；回执清理不影响已保存消息的长期读取。
- [ ] AC3（R5）：账号 B 看不到 A 的缓存、草稿、附件或生成内容，无法查询/订阅/停止 A 的任务；覆盖两个退出入口、跨标签页身份变化及退出前未完成上传的迟到回调，不以手动注入状态代替验证。
- [ ] AC4（R4）：停止保留部分文字；生成中删除话题/助手取消上游。终态与删除竞争时，数据不重现；图片失败/停止/迟到写入不遗留本轮已知的无引用文件。
- [ ] AC5（R3、R6）：已有内容恢复与实时订阅交接、重复提交和同一进程重复调度时，健康任务文字不重复、不倒退，消息身份不变；同一任务不重复执行。同话题活跃时的新生成或上下文变更被服务端拒绝，不同话题可并行。
- [ ] AC6（R1、R7）：恢复后的 groupId、groupCreatedAt、选中版本及 metadata 与原回合一致；思考、工具、引用、附件、截断反馈、图片结果、后台标题和压缩边界不丢失；桌面/触屏滚动行为无回归。
- [ ] AC7（R8）：当前 Docker/Node + PostgreSQL 正常更新后自动运行，无新增组件或人工启用；至少5个不同话题同时提交可开始生成，不等待前4个完成，也不等待周期扫描才正常启动。无浏览器仍能完成任务；慢订阅者不会造成无界内存积压。长回复不因频繁全量传输产生明显带宽/解析退化，空闲隐藏页面不持续高频轮询。临时恢复数据自动回收，不永久保留逐Token日志或要求人工清理。
- [ ] AC8（R9）：运行中终止执行进程后，恢复最近持久化内容并显示中断，不再调用模型；停止中的失联任务收尾为已停止。未领取的排队任务不会丢失。明确区分未落库尾部与已保存内容。

## 不在本期范围

- 多应用实例之间的实时恢复、接管或分布式调度。
- 供应商连接跨服务端进程重启的无损续传、未落库尾部的零丢失承诺。
- 已开始任务的自动重投或工具副作用重放；不扩大现有 SDK 的有限请求级重试策略。
- 未被服务端接受的请求自动重发；对话分叉、通知、计费看板及草稿自动持久化。
- Redis/外部队列/独立 Worker/任务管理面板、永久逐 Token 事件日志、通用兼容或调度框架。
- 通用双协议兼容框架或全面前端重写；保留现有聊天POST流响应及历史/停止接口的既有形状，新增恢复能力，不以升级为由要求旧页面先刷新才能正常提交。
- 不承诺强杀后直接降级到不认识新任务的旧二进制也能自动判定中断；新版重启故障收尾属于R9，二者不能混为一谈。
- 与本需求无关的重构、样式改动和用户文件修改。

## 关键边界与审阅状态

- 关闭浏览器不等于服务器故障：前者继续生成，后者可能只能恢复最近保存的部分并标中断。
- 图片请求依旧可能在生成完成前没有可展示的图片；不得用不完整批次冒充已完成。
- 详细状态机、存储/API合同、自动调度、退出整页边界和发布/回滚设计已写入 `design.md`；规模、阶段与验证门禁见 `implement.md`。
- 本期仅覆盖当前单应用实例，用户和话题仍可并行；跨实例候选条目已从design/implement删除。
- 服务端内存维护当前完整消息状态，例如`ABC`；在线时发送新内容，重连恢复当前状态后接续增量，不保留历史快照数组或所有原始事件。SDK协议适配细节见design.md。
- 实时恢复不依赖逐次落库或每500ms全文更新。接受和终态持久化；低频中途检查点只负责进程故障保留，独立于浏览器恢复，不擅自取消全部中途保存。
- G1只验证SDK能否接回同一活跃消息并继续输出、不重复追加消息；最小隔离实验已通过。数据库成本、内存/GC、缓存释放、慢订阅及跨实例实验不作为本轮规划门禁。
- 回执期限已定案：只接受固定有效期内的新请求ID；活跃任务不因时间到期删除，终态回执保留至少24小时再自动回收；回收后旧ID不能重新发起生成或重建已删除话题。具体期限判定、时钟处理和清理顺序见design.md第4节。
- 用户安排实际功能/浏览器交互回归由用户手测，不再列为规划阻塞项；实施仍运行类型、构建与核心数据一致性等自动检查，未手测项如实交付。
- 用户已确认：将当前单页面的“同一话题生成中不能再次生成/改上下文”扩展到跨标签页/API，冲突返回409；不同话题不共享生成名额。该行为约束已纳入随后获批的实施范围。
- 产品核心目标未变。实施、返修和自动检查记录见 `implement.md` 第11节；用户手测、提交与归档仍待后续确认。
