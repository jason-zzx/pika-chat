# 聊天滚动行为对齐主流 AI 聊天

## 背景

聊天消息溢出容器高度后，滚动行为与主流 AI 聊天（ChatGPT、LobeHub）差距明显：

1. 发送新消息后，新消息停留在视口底部，而不是像主流产品那样移到视口最上方（看起来像"第一条消息"）。
2. AI 回复增长超过一屏时，视图没有持续跟随流式输出向下滚动。
3. 思考（reasoning）区域内部文字会自滚，但思考区域高过外部容器时，外部容器不向下滚动。
4. 进入已有 topic 时停留在内容顶部，需要手动滚到底部看最新回复。

## 需求

### R1 发送置顶（用户消息，而非 AI 回复）

发送消息后，自动将**用户发送的消息**滚动到容器可见区域最上方。不能只把 AI 回复顶到最上方而看不到用户消息。

- 回复在预留区域内生长时，用户消息保持钉在视口顶部；
- 仅当回复高度超过预留区域后，才开始跟随回复尾部向下滚动。

### R2 流式跟随

回复内容（正文 + 思考块）超过容器高度时，持续自动向下滚动跟随最新输出；思考区高度变化同样驱动外容器滚动。

### R3 用户滚动优先

- 流式期间用户主动向上滚动（滚轮 / 触摸）即解除跟随，自由阅读历史；
- 滚回底部时恢复跟随；
- 程序化滚动（发送定位、跟随输出）绝不能误触发"解除跟随"。

### R4 回答结束后的预留区（spacer）处理

对齐 ChatGPT / LobeHub：

- 回答结束后预留区保留，用户消息保持置顶；
- 用户向上滚动时，预留区高度随滚动距离等量缩减，直至清零；
- 缩减过程视觉平滑，无抖动；
- 预留区耗尽后回滚到底部，回复下方不再有空白死区。

### R5 进入 topic 自动落底

从侧边栏进入（或刷新）已有 topic 时，自动将聊天内容滚动到最底部；mermaid / 数学公式 / 图片等异步渲染撑高内容时保持吸底，直到用户主动向上滚动。

## 约束

- C1：程序化滚动不得与用户手势检测互相干扰（避免 pin/unpin 打架）。
- C2：滚动过程中的高度调整必须与滚动同帧生效，不允许经 React 状态回环晚一帧（视觉抖动）。
- C3：中间消息（非尾部）的重新生成不得把视图拽到底部。
- C4：草稿话题发送后 replaceState 同步 URL 的流程不得被滚动逻辑打断。
- C5：移动端触摸滚动与桌面滚轮行为一致。

## 验收标准

- A1：发送后用户消息距视口顶部 ≈16px（容器 padding），短回复全程保持置顶。
- A2：长回复（正文+思考超过预留区）流式全程 `scrollHeight - scrollTop = clientHeight`（吸底）。
- A3：流式中向上滚动即停跟，内容继续增长视图不动；滚回底部恢复跟随。
- A4：回答结束后向上滚动，预留区缩减量 == 滚动量，距底部距离不变（内容无跳动）；耗尽后底部无死区。
- A5：上滚过程中无任何程序化 scrollTop 写回（无抖动源）。
- A6：进入含异步渲染内容（26 个 mermaid 图）的 topic，渲染波动期间每个采样点都在底部。
- A7：`tsc --noEmit`、`eslint`、`vitest run src/components/chat/`（115 个测试）全过。
